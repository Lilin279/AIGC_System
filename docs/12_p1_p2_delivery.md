# P1/P2 客户化与竞赛创新交付说明

## 交付结论

本轮将 P0 的“登录后直接访问课程”原型升级为学校客户可理解的三层业务模型：课程负责内容和图谱，教学班负责学期、教师和学生，学习记录按学生与教学班隔离。管理员不再复用教师界面。

## P1 闭环

1. 教师上传课件后创建持久化抽取任务，任务状态为排队、解析、抽取、融合、待审核、完成或失败。
2. 系统生成候选版本；教师确认前，学生继续访问最近一次已确认版本。
3. 节点、关系和文档分片保存来源。删除课件时预览可移除、共享和人工修订数量。
4. 默认同步回滚仅删除单一课件来源且未被人工修改的内容；保留图谱时标记来源不完整。
5. 课程可开设多个教学班，支持主教师、协作教师、班级码、批量导入、人数与平均进度。
6. 学生自注册直接激活；教师注册待审核；批量导入账号使用学号登录并首次强制改密。
7. 个人中心、反馈工单、附件、状态流转、站内通知和审计日志构成客户服务闭环。

## P2 主创新

- 可溯源 GraphRAG：SQLite FTS5 中文 2/3-gram 索引与 BM25 排序、知识点匹配和图谱邻居扩展联合构造证据。
- 回答返回课件名、页码、引用片段、知识点、关系证据和置信提示。
- 图谱质量评分覆盖重复率、孤立节点率、关系覆盖和来源覆盖。
- 学习诊断依据班级进度识别薄弱节点，结合前置关系生成路径和练习。
- OCR 保留扫描 PDF 的页码；Neo4j 只同步已确认版本，二者均为可选增强。

## 当前边界

- 已按单学校实现，核心表均包含组织字段；多学校租户隔离仍需单独安全评审。
- SQLite 适合比赛与单校试点；高并发生产环境建议迁移 PostgreSQL 与对象存储。
- 练习生成已接入 DeepSeek 证据约束 JSON 输出；未配置或调用失败时回退为明确标记的规则版本。
- 邮件/短信验证、找回密码、生产级病毒扫描和内容安全平台不在本轮范围。

## 验收路径

教师上传课件 -> 生成候选图谱 -> 审核应用 -> 创建教学班 -> 导入学生 -> 学生学习与问答 -> 删除错误课件并同步回滚 -> 管理员查看审计与处理工单。
