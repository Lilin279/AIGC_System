# P0 核心系统交付清单

## 本轮目标

把“能演示的原型”升级为具备账号边界、业务权限和可靠持久化的客户版 MVP 基础，为后续真实 AIGC、GraphRAG 和教学分析提供稳定底座。

## 已完成

- SQLite 关系数据模型：用户、会话、课程、资料、知识点、关系、学习进度。
- 账号系统：学生注册、账号密码登录、会话恢复、主动退出、7 天过期令牌。
- 密码安全：PBKDF2-SHA256 加盐哈希，不保存明文密码。
- 服务端权限：学生只读已发布课程；教师只管理本人课程；管理员可管理全局课程。
- 课程发布规则：新课先进入草稿；发布前至少需要 3 个知识点和 1 条知识关系。
- 数据隔离：掌握状态按“学生 + 课程 + 知识点”保存，教师图谱不显示学生掌握状态。
- 文件治理：限定扩展名、空文件校验、20 MB 大小限制、安全文件名和资料归属校验。
- 图谱治理：关系两端必须属于当前课程，禁止自环与重复关系，删除节点时级联清理关系和进度。
- 自动化验证：未登录拦截、角色越权、教师发布流程、双学生进度隔离。
- 浏览器验收：教师端、学生端、刷新后进度持久化、移动端无横向溢出、图谱快速切换无报错。

## P0 验收标准

1. 未登录调用业务 API 返回 401。
2. 学生创建或修改课程返回 403。
3. 教师无法管理其他教师课程。
4. 草稿课程不向学生显示，满足图谱条件后可发布。
5. 两个学生对同一知识点的掌握状态互不影响。
6. 刷新页面后登录状态与学习进度保留，退出后原令牌失效。
7. 前端正式构建通过，核心后端测试全部通过。

## 暂不属于 P0

- DeepSeek / 通义千问真实抽取与流式问答。
- OCR 扫描件识别、复杂表格和公式解析。
- Neo4j 双写或图数据库迁移。
- 教师邀请码、学校管理员审核、密码找回、短信或邮箱验证。
- 生产部署的 HTTPS、域名、对象存储、监控告警和自动备份。

这些内容进入 P1/P2，其中真实 LLM 与 OCR 需要 API Key 或服务选型时再由项目负责人提供配置。
